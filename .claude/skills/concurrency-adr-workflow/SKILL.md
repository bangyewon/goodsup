# 동시성/정산 ADR + 적대적 검증 워크플로

이 프로젝트(CLAUDE.md)는 동시성·정산·트랜잭션 경계처럼 되돌리기 어려운 설계를 코드부터 쓰지 않고
ADR로 먼저 비교·확정한 뒤, 구현 직후 Claude를 적대적 검증자로 써서 반례를 찾는 절차를 강제한다.
이 스킬은 그 절차를 매번 처음부터 떠올리지 않도록 순서와 템플릿을 고정해둔 것이다.

## 0단계 — ADR 대상인지 먼저 판단

다음 중 하나라도 해당하면 ADR 대상이다. 아니면 바로 구현해도 된다(과잉 적용 금지).

- 동시성 제어 전략을 새로 고르거나 바꾼다 (락 종류, 락 범위, 재시도 정책)
- 마감/정산처럼 상태 전이가 되돌아가면 안 되는 배치 로직을 새로 만든다
- 트랜잭션 경계(무엇을 트랜잭션 안에 넣고 무엇을 밖에 둘지)를 새로 정한다
- 결제 상태 모델(전이 가능한 상태와 전이 조건)을 바꾸거나 확장한다

이미 결정되고 실측까지 끝난 것(`docs/adr/0001`의 비관적 락, `docs/adr/0004`의 outbox fan-out 등)을
그대로 재사용하는 코드는 ADR 대상이 아니다 — 기존 ADR을 인용만 하면 된다.

## 1단계 — ADR 초안 작성

1. `docs/adr/`를 확인해 다음 번호를 정한다 (`ls docs/adr` 기준 4자리 순번).
2. `references/adr-template.md`를 복사해 `docs/adr/00NN-<슬러그>.md`로 저장한다.
3. **상태는 반드시 "논의 중 (구현 전 초안 — 사람 확인 필요, 아직 코드 작성 안 함)"으로 시작한다.**
4. 비교 대상(대안들)과 각각의 트레이드오프를 채운다 — 기각한 대안도 왜 기각했는지 남긴다
   (`docs/adr/0006`처럼 논의 과정 자체가 나중에 근거 자료가 된다).
5. 결정/트레이드오프 절은 비워두고 사람 확인을 기다린다. **여기서 멈추고 사람에게 확인을 요청한다.**

## 2단계 — 확인 후 구현

사람이 ADR 초안을 확인하면 구현을 시작한다. 이 시점에 이미 실측 비교가 끝난 동시성 로직
(참여 재고 차감 = `GoodsFundingRepository.findByIdForUpdate`)은 새로 설계하지 말고 그대로 재사용한다.

## 3단계 — 구현 직후 적대적 검증

구현이 끝나면 정상 동작을 가정하지 말고 반례부터 찾는다. 이 프로젝트에는 이 역할 전용
서브에이전트(`bug-reproducer`)가 있다 — "이 로직 깨뜨려봐" 요청으로 호출하면 실패 가능한 실행
순서와 엣지케이스를 제안하고, 실제 재현 가능한 것만 골라 재현·기록까지 담당한다(버그 수정은
직접 하지 않음). 순서:

1. `bug-reproducer`에게 방금 구현한 로직(락 획득 지점, 상태 전이 지점, 트랜잭션 경계)을 넘기고
   실패 시나리오 후보를 받는다.
2. 사람이 실제로 재현할 가치가 있는 시나리오를 고른다.
3. `ExecutorService` 기반 동시 호출 테스트 또는 Testcontainers 통합 테스트로 구현한다.
4. 실제 실행 결과와 예측을 비교한다 — **Claude의 예측 자체를 근거로 결론 내리지 않는다.**
5. 재현된 버그는 원인을 분석해 수정하고, 동일 시나리오를 재실행해 해결을 검증한다.

## 4단계 — 기록

재현 여부와 무관하게 모든 시나리오를 기록한다.

1. 다루는 주제(이슈)의 로그 파일이 `docs/experiments/adversarial-test-log-<주제>.md`에 이미
   있으면 표에 행을 추가하고, 없으면 `references/adversarial-test-log-template.md`로 새로 만든다.
2. 새 파일을 만들었다면 `docs/experiments/adversarial-test-log.md`(인덱스)에 한 줄 등록한다.
3. ADR 문서로 돌아가 "실험 설계"에서 예고했던 항목의 실측 결과를 "트레이드오프" 절에 채우고,
   상태를 "채택됨"으로 바꾼다.

## 불변식 검증이 필요하면

정합성 불변식("참여 수량은 목표 수량을 절대 초과하지 않는다" 류)은 위 예제 기반 테스트와
별개로 jqwik stateful property test로 보완한다 — ExecutorService 테스트를 대체하지 않고,
사람이 미리 떠올리지 못한 커맨드 시퀀스 반례를 찾는 용도다. 재현된 반례는 반드시
example-based 회귀 테스트로도 고정한다.
