## 회고

- **기대와 다른 결과**: 락 경합이나 재고 초과 같은 동시성 버그를 찾을 줄 알았는데, 실제 버그(#1)는 1인당
  최대 수량을 이번 요청 수량만으로 검사하던 검증 누락이었다. 순차 호출로도 재현되는 문제라 동시성과는
  무관했다. 동시성을 중심으로 시나리오를 뽑았어도 일반 로직 결함이 같이 나온다는 걸 알았다.
- **ADR-0001 선택과의 관계**: #2, #3(락 TTL 만료, 프로세스 크래시 시 락 잔존)은 Redisson을 썼다면
  따져야 했을 시나리오다. DB 비관적 락은 트랜잭션에 묶여 있어 해당하지 않았다. 다만 이건 DB 락을
  쓰는 동안만 성립하므로, 다른 로직에 Redisson을 쓰게 되면 다시 검토해야 한다.
- **아직 모르는 것**: #5(락 대기 타임아웃)는 동시 200건·단일 인스턴스에서만 확인했다. 그보다 큰 규모에서는
  재현될 수 있어서, 트래픽이 늘면 같은 시나리오를 다시 돌릴 예정이다.
